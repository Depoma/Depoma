## 3. Technical Review & Architectural Consistency Notes

1. **Ledger Quantity Invariant (`quantity > 0`):** In `stock_movements`, the `quantity` column enforces `CHECK (quantity > 0)` across all movement types (`IN`, `OUT`, `ADJUSTMENT`), representing the magnitude of the transaction. The direction of change is determined by `movement_type`, and the exact post-transaction state is captured in `balance_after`.
2. **Strict Separation of UI Language vs. System Data Formats:** While the end-user interface is rendered in Persian (RTL) with Jalali dates (`PROTOTYPE_SPECIFICATION.md`), all database columns (`DATABASE_DESIGN.md`), REST API payloads (`API_SPECIFICATION.md`), and domain error codes (`INSUFFICIENT_STOCK`, `FORBIDDEN_WAREHOUSE_ACCESS`) use standardized English identifiers and `ISO 8601 UTC` timestamps.
3. **Server-Side Warehouse Access Enforcement:** Every inventory and warehouse read/write endpoint enforces operator scoping against `warehouse_operators` at the service layer, guaranteeing that client-side parameter manipulation cannot bypass warehouse boundaries.
